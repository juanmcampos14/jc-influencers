# ADR-006 · Fuera de alcance devuelve 404, no 403

**Fecha:** 2026-08-25 · **Estado:** aceptada

## Contexto

El brief pide que los tests de acceso cruzado fallen "con `403` o `404`, sin revelar si el recurso existe".

## Problema

Un `403 Prohibido` sobre `/campanas/abc123` confirma que `abc123` existe. Recorriendo ids se puede mapear
cuántas campañas tiene la competencia, aunque no se vea su contenido.

## Decisión

Dos respuestas con significados distintos:

| Situación | Respuesta |
| --- | --- |
| El recurso pertenece a un cliente **fuera del alcance** del usuario | **404** — para ese usuario, no existe |
| El recurso está **dentro del alcance** pero falta la capacidad para la acción | **403** — existe, pero no puede |

El mensaje del 404 es siempre `"No encontrado"`, sin nombrar el recurso.

Un usuario de cliente que abre una ruta del panel interno **no** recibe 403: el layout lo redirige a su
portal. No hay pista de que esa sección exista.

## Consecuencias

- No se puede enumerar recursos de otro tenant.
- El 403 sigue siendo útil donde corresponde: un lector que intenta aprobar recibe "no tenés permiso",
  que es un mensaje accionable.
- **Costo:** depurar un permiso mal configurado es un poco más incómodo, porque un 404 puede significar
  "no existe" o "no es tuyo". Se compensa con la auditoría, que registra el intento.
